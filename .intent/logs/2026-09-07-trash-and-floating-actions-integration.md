## Review and resulting implementation

The four directory actions overlay the non-scrolling tree area and align with its first row at rest. Browser metadata supplies the provider's canonical home-trash files directory before navigation or sidebar restoration. Client deletion classification covers the entire parent trash root, including nested directories and info records; the imported implementation classified only files descendants. Host deletion refuses recoverable requests there and protects root/files/info, including paths through parent aliases. Provider failures reject operations rather than silently removing protection; a specifically unsupported platform retains ordinary deletion behavior.

Restoration reads a regular, non-symlink UTF-8 record and accepts one Path within its Trash Info group. Percent decoding must produce an absolute path without NUL, and the destination must be outside trash. Parent links are resolved while the final entry remains a rename/unlink target, allowing restoration of a trashed symbolic link itself. Missing parents, malformed or missing records, nested entries and occupied destinations preserve the entry and its record. The [Freedesktop trash specification](https://specifications.freedesktop.org/trash/latest/) defines the home files/info relationship and encoded original path.

Restoration and existing creation/move/removal all use the shared user-files mutation queue. Manager owns no content API, filesystem source, Viewer import or parallel queue. Moves and restores share one no-clobber helper with no copy fallback. GNU 9.2–9.4 can return nonzero for a skipped destination, while other versions can return zero without verbose output; both paths report an occupied destination. The local executable is GNU coreutils 9.4. The [GNU mv reference](https://www.gnu.org/s/coreutils/manual/html_node/mv-invocation.html) describes skip and no-copy behavior. Configured subprocesses receive an environment without credential-named variables.

Successful restoration and permanent deletion of a direct files child remove its matching info record. Nested deletion retains the top-level record. Missing records after a completed operation need no cleanup; other unlink failures explicitly identify the completed file operation and remaining record. A file operation and record cleanup are separate filesystem changes, so this is not a cross-process transaction. External processes can replace paths between checks and mutation, as with the existing named-path deletion behavior.
